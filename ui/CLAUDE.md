# UI module

Flutter-клиент DTFool. Зависит от `logic/` через `path: ../logic`. Игра только онлайновая — клиент всегда подключается к серверу через WebSocket.

## Платформы и ориентация

- Целевая платформа — мобильные (iOS, Android), портретная ориентация.
- Десктоп (Linux/Mac/Windows) и web — поддерживаются как вторичные, layout рассчитан на узкий портретный экран и масштабируется до десктопа.

## Экраны

```
main.dart (запуск, загрузка AppSettings)
└── SetupScreen — выбор «Создать комнату» / «Войти по коду» / «Настройки»
    ├── SettingsScreen — никнейм, адрес сервера, конфиг колоды
    └── LobbyScreen — подключение, ожидание игроков, старт игры
        └── OnlineGameScreen — игровой стол
```

Локального оффлайн-режима нет. `GameScreen` удалён.

## Никнейм

- Хранится в `AppSettings.playerName` (`shared_preferences`).
- При первом запуске или при пустом значении автогенерируется как `Player_<NNN>` (`NNN` — три случайные цифры) и сохраняется.
- Передаётся в сообщениях `create_room` / `join_room`. Сервер отвечает в `room_state` / `game_state` массивом игроков с полями `id` (8-байтовый hex, машинный) и `nickname` (UI).
- Меняется в `SettingsScreen`.

## Игровой экран — раскладка

Портретный layout, `Stack` по всему экрану:

- **Левый верхний угол** — колода: закрытая карта рубашкой вверх; под ней, повёрнутая на 90°, лежит открытая козырная карта (`GameState.trumpCard`), наполовину выглядывающая. Рядом — счётчик оставшихся карт. Когда колода пуста — угол скрыт.
- **Правый верхний угол** — бита: закрытая карта со счётчиком сброшенных карт.
- **Игроки** располагаются по кругу. Координаты считаются от количества активных игроков (2–6). Свой игрок всегда снизу по центру; остальные сидят по кругу с тем же относительным порядком, что и в `GameState.players` (поворот, не пересортировка).
- **Чужой игрок** (`_PlayerSeat`): компактный виджет — несколько карт рубашкой вверх «веером» + никнейм + количество карт.
- **Активный игрок** (тот, чей сейчас ход / отбивается / держит токен подкида) — обводка пожирнее, без свечения.
- **Стол** — центральная зона `Stack`, пары «атака / защита» (защита смещена `(+16, +16)` поверх атаки).
- **Лог действий** — свёрнутая полоска над рукой с последним событием. По тапу — `BottomSheet` со всей историей текущей партии. Видно всем игрокам (вычисляется на клиенте по diff между `game_state`).
- **Контекстная панель действий** — над рукой, показывает только релевантные текущей фазе кнопки.
- **Рука игрока** снизу — `SingleChildScrollView` по горизонтали, карты отсортированы.

## Сортировка руки

Порядок мастей: `[♣, ♦, ♥, ♠]` минус козырная масть; козырная масть — в самый конец (правый край). Внутри масти — по возрастанию номинала.

Сортировка чисто визуальная, не мутирует данные с сервера.

## Карты — состояние отображения

`CardWidget` рендерит карту как:
- **Открытая** (`faceUp = true`): SVG-ассет лица из `assets/cards/{suit}_{rank}.svg`.
- **Закрытая** (`faceUp = false`): SVG-ассет рубашки из `assets/backs/{backSkinId}.svg`. Поле `backSkinId` заложено для будущего расширения (разные рубашки в одной колоде); сейчас всегда `'default'`.

Параметры визуализации: `selected`, `highlighted` — меняют толщину рамки. Размер карты параметризован (для руки, миниатюр в посадке игрока, на столе).

## Жесты и ввод

- Drag — основной способ ввода. Drag-data — `card.id` (стабильный между перерисовками; индекс в руке меняется при сортировке).
- Drop карты на зону стола → атака / подкид / перевод (зависит от фазы).
- Drop карты поверх конкретной карты атаки на столе → защита.
- Tap по карте в руке → toggle multi-select (для подкида сразу нескольких карт одного номинала).

## Анимации

Все перемещения карт анимированы через overlay-`Stack` с `AnimatedPositioned`, индексируемый по `card.id`:
- раздача (карты летят из колоды в руки игроков),
- атака/подкид (из руки на стол),
- защита (на атаку со смещением),
- взять (со стола в руку отбивающегося),
- бито (со стола в правый верхний угол),
- добор (по одной из колоды в руки).

Длительность ~200 мс на карту, overlap ~50 мс. Настройка скорости/отключения пока не предусмотрена.

`GlobalKey` на каждый якорь (углы, посадки, слоты в руке) — для пересчёта координат через `RenderBox.localToGlobal`.

## Зависимости логики и протокола

- `GameState.trumpCard: Card?` — конкретная козырная карта, пока остаётся в колоде. Нужна для отрисовки в углу. Расширение `logic/`.
- `gameStateMsg.trumpCard` — сериализуется сервером.
- `players[i].nickname` — приходит вместе с `id` и `handSize`.
